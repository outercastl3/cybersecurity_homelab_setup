# Incident Report — DVWA Web Application Attack 21.06.26
Detection was performed through manual log review of nginx access logs 
forwarded from the DMZ Docker environment to Wazuh. Automated alerting 
was not available due to a detection gap identified during this incident 
— see Lessons Learned.

## Initial Detection
During routine review of /var/log/dvwa_access.log on 21.06.26, unusual 
traffic patterns were identified originating from 192.168.1.30. 
High volume of POST requests to /login.php indicated a potential brute 
force attempt, prompting further investigation.

## Investigation

### Reconnaissance
At 11:43:12 an Nmap scan was detected originating from 192.168.1.30 
targeting dvwa.lab.local, visible through rapid sequential GET requests 
to multiple ports and paths:
```
192.168.1.30 - - [21/Jun/2026:11:43:12 +0000] "GET / HTTP/1.1" 302 0 "-" "Mozilla/5.0 (compatible; Nmap Scripting Engine)"
192.168.1.30 - - [21/Jun/2026:11:43:12 +0000] "GET /login.php HTTP/1.1" 200 926 "-" "Mozilla/5.0 (compatible; Nmap Scripting Engine)"
```
Directory enumeration followed at 11:44:35 via wordlist bruteforcing 
of common paths:
```
192.168.1.30 - - [21/Jun/2026:11:44:35 +0000] "GET /admin HTTP/1.1" 404 0
192.168.1.30 - - [21/Jun/2026:11:44:35 +0000] "GET /config HTTP/1.1" 404 0
192.168.1.30 - - [21/Jun/2026:11:44:35 +0000] "GET /backup HTTP/1.1" 404 0
192.168.1.30 - - [21/Jun/2026:11:44:35 +0000] "GET /setup.php HTTP/1.1" 200 0
192.168.1.30 - - [21/Jun/2026:11:44:35 +0000] "GET /phpinfo.php HTTP/1.1" 200 0
```

### Authentication Brute Force
Starting at 11:54:24 a high volume of POST requests to /login.php was 
observed from 192.168.1.30, consistent with automated credential stuffing:
```
192.168.1.30 - - [21/Jun/2026:11:54:24 +0000] "POST /login.php HTTP/1.1" 302 451
192.168.1.30 - - [21/Jun/2026:11:54:24 +0000] "GET /login.php HTTP/1.1" 200 941
192.168.1.30 - - [21/Jun/2026:11:54:28 +0000] "POST /login.php HTTP/1.1" 302 451
192.168.1.30 - - [21/Jun/2026:11:54:28 +0000] "GET /login.php HTTP/1.1" 200 941
192.168.1.30 - - [21/Jun/2026:11:54:31 +0000] "POST /login.php HTTP/1.1" 302 451
192.168.1.30 - - [21/Jun/2026:11:54:31 +0000] "GET /login.php HTTP/1.1" 200 941
```
302 redirect followed by 200 on /login.php indicates failed login — 
DVWA redirects back to login on failure. At 11:57:29 a successful 
authentication was observed — POST returned 302 redirect to index.php 
rather than back to login.php:
```
192.168.1.30 - - [21/Jun/2026:11:57:29 +0000] "POST /login.php HTTP/1.1" 302 451
192.168.1.30 - - [21/Jun/2026:11:57:29 +0000] "GET /index.php HTTP/1.1" 200 1623
```

### SQL Injection and Data Exfiltration
Following successful authentication, SQL injection attempts were 
observed against the vulnerable input field at 12:03:15:
```
192.168.1.30 - - [21/Jun/2026:12:03:15 +0000] "GET /vulnerabilities/sqli/?id=%27&Submit=Submit HTTP/1.1" 200 1842
192.168.1.30 - - [21/Jun/2026:12:03:22 +0000] "GET /vulnerabilities/sqli/?id=1%27+OR+%271%27%3D%271&Submit=Submit HTTP/1.1" 200 2103
192.168.1.30 - - [21/Jun/2026:12:03:41 +0000] "GET /vulnerabilities/sqli/?id=1%27+ORDER+BY+1--&Submit=Submit HTTP/1.1" 200 1842
192.168.1.30 - - [21/Jun/2026:12:03:43 +0000] "GET /vulnerabilities/sqli/?id=1%27+ORDER+BY+2--&Submit=Submit HTTP/1.1" 200 1842
192.168.1.30 - - [21/Jun/2026:12:03:45 +0000] "GET /vulnerabilities/sqli/?id=1%27+UNION+SELECT+null%2C+null--+-&Submit=Submit HTTP/1.1" 200 1956
192.168.1.30 - - [21/Jun/2026:12:03:52 +0000] "GET /vulnerabilities/sqli/?id=1%27+UNION+SELECT+null%2C+database()--+-&Submit=Submit HTTP/1.1" 200 1978
192.168.1.30 - - [21/Jun/2026:12:04:01 +0000] "GET /vulnerabilities/sqli/?id=1%27+UNION+SELECT+user%2C+password+FROM+users%23&Submit=Submit HTTP/1.1" 200 2341
```
URL decoded payloads confirm UNION based SQL injection with successful 
database enumeration and credential exfiltration from the users table. 
Passwords returned were hashed with MD5.

### Command Injection and RCE
At 12:08:44 command injection attempts were observed against the 
ping utility input field:
```
192.168.1.30 - - [21/Jun/2026:12:08:44 +0000] "POST /vulnerabilities/exec/ HTTP/1.1" 200 1823
192.168.1.30 - - [21/Jun/2026:12:08:51 +0000] "POST /vulnerabilities/exec/ HTTP/1.1" 200 1967
192.168.1.30 - - [21/Jun/2026:12:08:58 +0000] "POST /vulnerabilities/exec/ HTTP/1.1" 200 2134
192.168.1.30 - - [21/Jun/2026:12:09:14 +0000] "POST /vulnerabilities/exec/ HTTP/1.1" 200 3821
```
POST body analysis confirmed chained commands using && operator — 
whoami, hostname, id, uname -a executed sequentially. At 12:09:14 
/etc/passwd was read and staged to /tmp/exfil.txt confirming full RCE.

## Containment
- 192.168.1.30 blocked at pfSense firewall level
- DVWA security level raised to prevent further exploitation
- Docker containers restarted to clear any staged files in /tmp
- Nginx access logs preserved as evidence

## Eradication
- No persistence mechanisms identified — attack was contained within 
  the Docker container
- /tmp/exfil.txt confirmed removed on container restart
- No lateral movement detected beyond the DMZ segment
- DMZ firewall rules confirmed — lab-lan block rule prevented any 
  further internal network access

## Detection Gap — Lessons Learned
- Wazuh successfully ingested Docker container logs via pipe forwarding 
  to /var/log/dvwa_access.log
- Custom detection rules 10007-10010 were developed for web attack 
  patterns however automated alerting did not fire during this incident
- Detection relied entirely on manual log review — a significant gap 
  in coverage for web application attack chains
- Recommended next steps:
  - Implement proper Wazuh decoder for Docker JSON wrapped log format
  - Validate and tune custom rules 10007-10010 against live traffic
  - Implement rate limiting on nginx to slow brute force attempts
  - Enforce input sanitization — DVWA security level should reflect 
    realistic hardened configuration in future scenarios
  - All domain service account passwords should be rotated following 
    credential access attempts
